## Как я могу помочь?

### 🐛 Сообщить о баге

1. Проверьте, не был ли баг уже сообщен в [Issues](https://github.com/yourusername/dmIntegroff/issues)
2. Если нет, создайте новый issue с:
   - Четким описанием проблемы
   - Шагами для воспроизведения
   - Ожидаемым и фактическим поведением
   - Версией Go и ОС
   - Логами (если применимо)

### 💡 Предложить улучшение

1. Создайте issue с тегом `enhancement`
2. Опишите:
   - Какую проблему решает предложение
   - Как это должно работать
   - Альтернативные решения, которые вы рассматривали

## Процесс разработки

### 1. Fork и клонирование

```bash
# Fork репозитория через GitHub UI

# Клонируйте ваш fork
git clone https://github.com/YOUR_USERNAME/dmIntegroff.git
cd dmIntegroff

# Добавьте upstream remote
git remote add upstream https://github.com/ORIGINAL_OWNER/dmIntegroff.git
```

### 2. Создайте ветку

```bash
# Обновите main
git checkout main
git pull upstream main

# Создайте feature ветку
git checkout -b feature/amazing-feature
# или
git checkout -b fix/bug-description
```

### 3. Настройте окружение

```bash
# Установите зависимости
go mod download

# Создайте .env файл
cp .env.example .env

# Запустите сервер
go run cmd/server/main.go
```

### 4. Внесите изменения

- Пишите чистый, читаемый код
- Следуйте существующему стилю
- Добавляйте комментарии к сложной логике
- Обновите документацию при необходимости

### 5. Тестируйте

```bash
# Форматирование
go fmt ./...

# Проверка
go vet ./...

# Тесты (когда будут добавлены)
go test ./...

# Запустите сервер и проверьте в браузере
go run cmd/server/main.go
```

### 6. Commit и Push

```bash
# Добавьте изменения
git add .

# Commit с понятным сообщением
git commit -m "✨ Add amazing feature"

# Push в ваш fork
git push origin feature/amazing-feature
```

### 7. Создайте Pull Request

1. Перейдите на GitHub в ваш fork
2. Нажмите "New Pull Request"
3. Заполните шаблон PR
4. Дождитесь ревью

## Стиль кода

### Go код

Следуйте стандартным соглашениям Go:

```go
// ✅ Хорошо
func ProcessWebhook(integrationID uint, payload map[string]interface{}) error {
    // Комментарий объясняет сложную логику
    var integration models.Integration
    if err := database.DB.First(&integration, integrationID).Error; err != nil {
        return fmt.Errorf("integration not found: %w", err)
    }
    
    // ...
    return nil
}

// ❌ Плохо
func process_webhook(id uint,p map[string]interface{})error{
var i models.Integration
database.DB.First(&i,id)
return nil
}
```

### Именование

- **Файлы**: `snake_case.go`
- **Функции**: `PascalCase` (экспортируемые), `camelCase` (внутренние)
- **Переменные**: `camelCase`
- **Константы**: `UPPER_SNAKE_CASE`

## Pull Requests

### Checklist перед созданием PR

- [ ] Код отформатирован (`go fmt ./...`)
- [ ] Нет ошибок линтера (`go vet ./...`)
- [ ] Тесты проходят (если есть)
- [ ] Добавлены комментарии к публичным функциям
- [ ] Обновлена документация (если нужно)
- [ ] Проверена работа в браузере
- [ ] Коммиты имеют понятные сообщения
- [ ] Ветка обновлена с main

### Шаблон PR

```markdown
## Описание
Краткое описание изменений

## Тип изменения
- [ ] Исправление бага
- [ ] Новая функциональность
- [ ] Критическое изменение (breaking change)
- [ ] Документация

## Как протестировано?
Опишите тесты, которые вы провели

## Скриншоты (если применимо)
Добавьте скриншоты UI изменений

## Checklist
- [ ] Код следует стилю проекта
- [ ] Проведен self-review
- [ ] Добавлены комментарии
- [ ] Обновлена документация
- [ ] Нет новых warnings
- [ ] Тесты проходят
```

### Процесс ревью

1. Maintainer проверит ваш PR
2. Могут быть запрошены изменения
3. Внесите изменения и push в ту же ветку
4. После одобрения PR будет смержен
