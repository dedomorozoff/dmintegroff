# Обновление: Каскадное удаление интеграций

## Что изменилось?

Теперь при удалении проекта автоматически удаляются все его интеграции. Это изменение делает управление проектами более логичным и предсказуемым.

### До обновления
- При удалении проекта интеграции оставались в системе без проекта (project_id = NULL)
- Требовалось вручную удалять интеграции

### После обновления
- При удалении проекта все его интеграции удаляются автоматически
- Пользователь получает предупреждение перед удалением
- Действие необратимо

## Как применить обновление?

### Вариант 1: Автоматическая миграция (рекомендуется)

```bash
# Остановите сервер
# Затем выполните миграцию

# Windows
dmintegroff.exe -migrate

# Linux/Mac
./dmintegroff -migrate
```

### Вариант 2: Ручная миграция

#### Для SQLite:
```bash
sqlite3 dmIntegroff.db < migrations/004_cascade_delete_integrations_sqlite.sql
```

#### Для MySQL:
```bash
mysql -u username -p database_name < migrations/004_cascade_delete_integrations.sql
```

## Проверка работы

1. Создайте тестовый проект
2. Добавьте в него несколько интеграций
3. Удалите проект
4. Убедитесь, что все интеграции проекта также удалены

Подробная инструкция по тестированию: `tests/test_cascade_delete.md`

## Важные замечания

⚠️ **Внимание:**
- Это изменение влияет на поведение удаления проектов
- Убедитесь, что все пользователи знают о новом поведении
- Рекомендуется сделать резервную копию БД перед обновлением
- После применения миграции откат невозможен без потери данных

## Поддержка

Если у вас возникли проблемы с обновлением:
1. Проверьте логи приложения
2. Убедитесь, что миграция применена корректно
3. Проверьте структуру таблицы integrations
4. Для SQLite убедитесь, что foreign keys включены

## Откат изменений

⚠️ Откат не рекомендуется и может привести к потере данных!

Если необходимо вернуться к старому поведению, используйте миграцию 002 для восстановления `ON DELETE SET NULL`.
