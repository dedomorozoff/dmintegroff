# Миграции базы данных

## ⚠️ ВАЖНО: Консолидированная схема

Поскольку проект еще не в продакшене, все миграции были объединены в два основных файла схемы:

- **`schema_sqlite.sql`** - Полная схема SQLite со всеми таблицами и индексами
- **`schema_mysql.sql`** - Полная схема MySQL со всеми таблицами и индексами

Старые пронумерованные файлы миграций (001_*.sql, 002_*.sql и т.д.) сохранены для истории, но больше не используются.

## Применение схемы

### Через admin CLI (рекомендуется)

Проект использует GORM AutoMigrate для автоматического создания таблиц на основе Go моделей:

```bash
# Windows
dmintegroff.exe -migrate

# Linux/Mac
./dmintegroff -migrate
```

Или через интерактивное меню:
```bash
go run cmd/admin/main.go
# Выберите пункт "1. Выполнить миграцию базы данных"
```

### Ручное применение SQL схемы (опционально)

Если вы хотите создать базу данных вручную или используете другой инструмент:

**SQLite:**
```bash
sqlite3 dmintegroff.db < migrations/schema_sqlite.sql
```

**MySQL:**
```bash
mysql -u username -p database_name < migrations/schema_mysql.sql
```

**Примечание:** SQL файлы схемы предоставлены для справки и ручной установки. Основной способ миграции - через GORM AutoMigrate (см. выше).

## Обзор схемы

Консолидированная схема включает следующие таблицы:

### 1. **users** - Пользователи
- Аутентификация и авторизация
- Поддержка демо-пользователей с временным доступом
- Роли: admin, specialist

### 2. **projects** - Проекты
- Организация интеграций по проектам
- Связь с создателем проекта

### 3. **integrations** - Интеграции
Основная таблица с полной конфигурацией:
- **Базовые поля:** name, webhook_token, source_api, target_api, mapping_config
- **Аутентификация:** OAuth 2.0, Bearer Token, Basic Auth
- **Безопасность вебхуков:** Проверка подписей (HMAC)
- **GraphQL:** Поддержка клиента и сервера GraphQL
- **GraphQL Enrichment:** Обогащение REST API данными из GraphQL
- **Кастомизация:** Произвольные заголовки, шаблоны (JSON/XML/Text)
- **Режимы работы:** listening (вебхук), polling (опрос API)

### 4. **integration_outputs** - Множественные выходы
- Несколько целевых API для одной интеграции
- Условная маршрутизация (condition)
- Приоритеты выполнения
- Независимая аутентификация для каждого выхода

### 5. **request_logs** - Логи запросов
- История всех входящих и исходящих запросов
- Заголовки, тела запросов/ответов, статус-коды
- Фильтрация по типу (request/response/error)

### 6. **webhook_tests** - Тестирование вебхуков
- Временные эндпоинты для тестирования
- Автоматическое истечение срока действия

### 7. **webhook_test_requests** - Захваченные тестовые запросы
- Все запросы, отправленные на тестовый вебхук
- Полная информация о методе, заголовках, теле

## Основные возможности

### Аутентификация
- **OAuth 2.0:** Client Credentials, Authorization Code
- **Bearer Token:** Статический токен
- **Basic Auth:** Username/Password
- Автоматическое обновление токенов OAuth

### GraphQL
- **Клиент:** Отправка GraphQL запросов к внешним API
- **Сервер:** Прием GraphQL запросов через вебхук
- **Enrichment:** Обогащение REST данных через GraphQL запросы
- Интроспекция схемы и валидация

### Безопасность
- Проверка подписей вебхуков (HMAC-SHA256/SHA512)
- Фильтрация HTTP методов
- Скрытие чувствительных данных в логах

### Трансформация данных
- JSON Path маппинг
- Шаблоны вывода (JSON/XML/Text/Custom)
- Условная маршрутизация
- Множественные выходы с приоритетами

## Миграция существующих данных

Если у вас уже есть база данных со старыми миграциями:

1. **Сделайте резервную копию!**
   ```bash
   # SQLite
   cp dmintegroff.db dmintegroff.db.backup
   
   # MySQL
   mysqldump -u username -p database_name > backup.sql
   ```

2. **Проверьте текущую схему** - убедитесь, что все таблицы и поля присутствуют

3. **Если нужно пересоздать базу:**
   ```bash
   # SQLite - удалить и создать заново
   rm dmintegroff.db
   sqlite3 dmintegroff.db < migrations/schema_sqlite.sql
   
   # MySQL - удалить все таблицы и создать заново
   # (будьте осторожны - это удалит все данные!)
   ```
