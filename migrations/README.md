# Миграции базы данных

## Применение миграций

### Автоматическая миграция (рекомендуется)

Для новых установок или обновления структуры БД используйте admin CLI:

```bash
# Windows
dmintegroff.exe -migrate

# Linux/Mac
./dmintegroff -migrate
```

Или через интерактивное меню:
```bash
go run cmd/admin/main.go
# Выберите пункт "1. Выполнить миграцию базы данных"
```

### Ручное применение миграций

Если вы хотите применить миграции вручную или у вас уже есть данные в БД:

#### SQLite

```bash
sqlite3 dmIntegroff.db < migrations/004_cascade_delete_integrations_sqlite.sql
```

#### MySQL

```bash
mysql -u username -p database_name < migrations/004_cascade_delete_integrations.sql
```

## История миграций

### 006_add_demo_users (2024-12-01)
**Описание:** Добавление поддержки демо-режима с временными пользователями.

**Изменения:**
- Добавлено поле `is_demo` (BOOLEAN) - флаг демо-пользователя
- Добавлено поле `expires_at` (DATETIME) - время истечения срока действия
- Создан индекс на `expires_at` для быстрой очистки

**Применение:**
```bash
# SQLite
sqlite3 dmintegroff.db < migrations/006_add_demo_users_sqlite.sql

# MySQL
mysql -u username -p database_name < migrations/006_add_demo_users.sql
```

**Документация:** См. `docs/DEMO_MODE.md` для подробной информации о демо-режиме.

### 005_add_output_template (2024-11-30)
**Описание:** Добавление поддержки шаблонов вывода для интеграций.

### 004_cascade_delete_integrations (2024-11-30)
**Описание:** Изменение поведения при удалении проекта - теперь все интеграции проекта удаляются автоматически.

**Изменения:**
- Изменен внешний ключ `project_id` в таблице `integrations`
- Старое поведение: `ON DELETE SET NULL` (при удалении проекта project_id становился NULL)
- Новое поведение: `ON DELETE CASCADE` (при удалении проекта удаляются все его интеграции)

**Важно:** Эта миграция изменяет поведение удаления проектов. Убедитесь, что вы понимаете последствия перед применением.

### 003_make_project_required (2024-11-29)
**Описание:** Сделать поле project_id обязательным для всех интеграций.

### 002_add_projects (2024-11-29)
**Описание:** Добавление таблицы проектов и связи с интеграциями.

### 001_initial_schema (2024-11-29)
**Описание:** Начальная схема базы данных (пользователи, интеграции, логи).

## Проверка применения миграций

После применения миграции 004 проверьте, что каскадное удаление работает:

1. Создайте тестовый проект
2. Добавьте в него несколько интеграций
3. Удалите проект
4. Убедитесь, что все интеграции проекта также удалены

## Откат миграций

⚠️ **Внимание:** Откат миграции 004 может привести к потере данных!

Если вам нужно вернуться к старому поведению (`ON DELETE SET NULL`), используйте соответствующие SQL команды из миграции 002.
