# Консолидация миграций

**Дата:** 2024-12-09  
**Статус:** Завершено ✅

## Что было сделано

Все пронумерованные файлы миграций (001-014) были объединены в два консолидированных файла схемы:

1. **`schema_sqlite.sql`** - Полная схема для SQLite
2. **`schema_mysql.sql`** - Полная схема для MySQL

## Причина

Проект еще не в продакшене, поэтому имеет смысл упростить структуру миграций и иметь единую точку входа для создания базы данных.

## Что изменилось

### До
```
migrations/
├── 001_initial_schema_sqlite.sql
├── 001_initial_schema.sql
├── 002_add_projects_sqlite.sql
├── 002_add_projects.sql
├── 003_add_request_headers_sqlite.sql
├── ... (всего 35+ файлов)
```

### После
```
migrations/
├── schema_sqlite.sql          # Консолидированная схема SQLite
├── schema_mysql.sql           # Консолидированная схема MySQL
├── README.md                  # Обновленная документация
└── legacy/                    # Старые миграции (для истории)
    ├── README.md
    ├── 001_initial_schema_sqlite.sql
    ├── 001_initial_schema.sql
    └── ... (все старые файлы)
```

## Преимущества

1. **Простота** - Один файл вместо десятков
2. **Ясность** - Легко увидеть полную структуру БД
3. **Быстрота** - Быстрое развертывание новых инстансов
4. **Меньше ошибок** - Нет риска пропустить миграцию
5. **Легче поддерживать** - Один источник правды

## Обратная совместимость

- Проект использует GORM AutoMigrate, поэтому код не затронут
- Старые файлы сохранены в `legacy/` для истории
- SQL схемы можно использовать для ручной установки

## Что дальше

Для новых изменений схемы:

1. **В разработке:** Обновляйте Go модели, GORM создаст таблицы автоматически
2. **Перед релизом:** Обновите `schema_sqlite.sql` и `schema_mysql.sql` в соответствии с моделями
3. **После релиза в продакшн:** Переходите на инкрементальные миграции (например, golang-migrate или goose)

## Проверка

Чтобы убедиться, что схема работает:

```bash
# Создайте тестовую БД
sqlite3 test.db < migrations/schema_sqlite.sql

# Проверьте таблицы
sqlite3 test.db ".tables"

# Удалите тестовую БД
rm test.db
```
