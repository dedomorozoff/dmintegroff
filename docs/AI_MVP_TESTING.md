# 🧪 Тестирование AI MVP

Инструкция по тестированию базового AI-ассистента в dmIntegroff.

---

## 🚀 Запуск системы

### 1. Настройка AI

Добавьте в `.env` файл:

```bash
# OpenRouter API (рекомендуется)
OPENROUTER_API_KEY=your-openrouter-api-key-here
OPENROUTER_MODEL=anthropic/claude-3.5-sonnet

# Или OpenAI API (fallback)
OPENAI_API_KEY=your-openai-api-key-here
```

**Получить API ключи:**
- OpenRouter: https://openrouter.ai/keys
- OpenAI: https://platform.openai.com/api-keys

### 2. Запуск сервера

```bash
cd dmintegroff
./dmintegroff.exe
```

Сервер запустится на http://localhost:8080

## 🧪 Тестовые сценарии

### Сценарий 1: Проверка статуса AI

1. Откройте http://localhost:8080
2. Войдите в систему (admin/admin)
3. Создайте новую интеграцию
4. На странице настройки маппинга нажмите **"🤖 AI Помощник"**
5. Проверьте что модальное окно открылось и показывает статус AI

**Ожидаемый результат:**
- Модальное окно открывается
- Показывается провайдер AI (OpenRouter/OpenAI)
- Чат доступен для ввода

### Сценарий 2: Базовый чат с AI

1. В открытом AI чате введите: "Хочу отправлять уведомления в Slack о новых заказах"
2. Нажмите "Отправить"
3. Дождитесь ответа AI

**Ожидаемый результат:**
- Сообщение отправляется
- Показывается индикатор "печатает"
- AI отвечает с предложениями по настройке Slack интеграции

### Сценарий 3: Анализ данных

1. Создайте интеграцию с образцом данных:
   ```json
   {
     "order_id": 123,
     "customer": "John Doe",
     "amount": 250.00,
     "email": "john@example.com"
   }
   ```
2. Откройте AI чат
3. Введите: "Проанализируй эти данные"

**Ожидаемый результат:**
- AI анализирует структуру данных
- Определяет типы полей (email, number, string)
- Предлагает маппинги для популярных API

### Сценарий 4: Генерация маппинга для Slack

1. С теми же данными введите: "Создай маппинг для Slack"
2. Дождитесь ответа

**Ожидаемый результат:**
- AI создает JSON шаблон для Slack webhook
- Предлагает правильный URL (hooks.slack.com)
- Форматирует сообщение с данными заказа
- Кнопка "Применить результат" становится активной

### Сценарий 5: Применение маппинга

1. После генерации маппинга нажмите **"Применить результат"**
2. Дождитесь подтверждения

**Ожидаемый результат:**
- Маппинг применяется к интеграции
- Страница перезагружается с обновленными настройками
- Target API URL обновляется на Slack webhook

## 🔍 Проверка API endpoints

### Статус AI
```bash
curl http://localhost:8080/api/ai/status
```

**Ожидаемый ответ:**
```json
{
  "configured": true,
  "provider": "OpenRouter (anthropic/claude-3.5-sonnet)",
  "available": true,
  "models": ["anthropic/claude-3.5-sonnet", "openai/gpt-4o", ...]
}
```

### Чат с AI
```bash
curl -X POST http://localhost:8080/api/ai/chat \
  -H "Content-Type: application/json" \
  -d '{
    "message": "Хочу интеграцию со Slack",
    "sample_data": {"order_id": 123, "customer": "John"}
  }'
```

### Анализ данных
```bash
curl -X POST http://localhost:8080/api/ai/analyze-data \
  -H "Content-Type: application/json" \
  -d '{
    "data": {"order_id": 123, "email": "test@example.com"},
    "format": "json"
  }'
```

## 🐛 Возможные проблемы

### AI недоступен
**Симптомы:** "❌ AI не настроен" или "❌ Ошибка подключения к AI"

**Решение:**
1. Проверьте API ключ в `.env`
2. Проверьте интернет соединение
3. Проверьте лимиты API (OpenRouter/OpenAI)

### Ошибка "no AI provider configured"
**Решение:** Убедитесь что установлен `OPENROUTER_API_KEY` или `OPENAI_API_KEY`

### Медленные ответы
**Причины:**
- Большие промпты (>1000 токенов)
- Медленная модель (попробуйте `openai/gpt-4o-mini`)
- Высокая нагрузка на API

### Некорректные маппинги
**Причины:**
- Недостаточно контекста в промпте
- Неподходящая модель
- Сложная структура данных
