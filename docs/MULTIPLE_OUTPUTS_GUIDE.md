# 🔀 Руководство по множественным выходам

## Описание

Множественные выходы (Multiple Outputs) позволяют одному webhook отправлять данные на несколько Target API с разными маппингами и настройками. Это мощная функция для интеграции с несколькими системами одновременно.

## Основные возможности

- ✅ Один webhook → несколько Target API
- ✅ Независимые маппинги для каждого выхода
- ✅ Параллельное выполнение выходов
- ✅ Независимая аутентификация для каждого выхода
- ✅ Приоритизация выполнения
- ✅ Включение/выключение отдельных выходов
- ✅ Тестирование каждого выхода отдельно
- ✅ Условное выполнение (в разработке)

## Как это работает

### Архитектура

```
Webhook → Интеграция → [Выход 1, Выход 2, Выход 3, ...]
                         ↓         ↓         ↓
                      Target 1  Target 2  Target 3
```

1. Webhook получает данные
2. Данные сохраняются как `SamplePayload` в интеграции
3. Каждый активный выход обрабатывает данные параллельно:
   - Проверяет условие выполнения (если задано)
   - Применяет свой маппинг/шаблон
   - Отправляет на свой Target API
4. Ошибка в одном выходе не влияет на другие

### Обратная совместимость

Если у интеграции нет выходов, используется основной маппинг интеграции (старое поведение). Это обеспечивает полную обратную совместимость.

## Использование

### 1. Создание выходов

1. Перейдите в список интеграций
2. Выберите интеграцию (должна быть активна или неактивна)
3. В меню действий выберите "Управление выходами"
4. Нажмите "Добавить выход"

### 2. Настройка выхода

При создании выхода укажите:

- **Название** - понятное имя для идентификации (например: "CRM Output", "Analytics")
- **Описание** - краткое описание назначения
- **Target API URL** - URL для отправки данных
- **HTTP метод** - GET, POST, PUT, PATCH, DELETE
- **Приоритет** - порядок выполнения (меньше = раньше)
- **Аутентификация** - OAuth 2.0, Bearer Token, Basic Auth или без аутентификации
- **Дополнительные заголовки** - JSON объект с кастомными заголовками

### 3. Настройка маппинга

После создания выхода:

1. Нажмите "Настроить маппинг" для выхода
2. Выберите тип маппинга:
   - **Шаблон** (рекомендуется) - гибкий шаблон с плейсхолдерами
   - **Простой маппинг** - поле-в-поле маппинг
3. Настройте трансформацию данных
4. Нажмите "Протестировать" для проверки
5. Сохраните маппинг

### 4. Управление выходами

На странице управления выходами вы можете:

- ✏️ **Редактировать** - изменить настройки выхода
- ⚙️ **Настроить маппинг** - изменить трансформацию данных
- 🧪 **Тестировать** - проверить работу выхода
- ⏸️/▶️ **Включить/Выключить** - временно отключить выход
- 🗑️ **Удалить** - удалить выход

## Примеры использования

### Пример 1: E-commerce заказ

Один webhook о новом заказе отправляет данные в 4 системы:

```
Webhook: новый заказ
├─ Выход 1: CRM (Salesforce)
│  └─ Маппинг: создать лид
│  └─ Priority: 0
│
├─ Выход 2: Analytics (Google Analytics)
│  └─ Маппинг: отправить событие покупки
│  └─ Priority: 1
│
├─ Выход 3: Email (SendGrid)
│  └─ Маппинг: отправить подтверждение заказа
│  └─ Priority: 2
│
└─ Выход 4: Warehouse (внутренняя система)
   └─ Маппинг: создать задачу на отгрузку
   └─ Priority: 3
```

### Пример 2: Мониторинг событий

Webhook о событии в системе отправляет уведомления:

```
Webhook: событие системы
├─ Выход 1: Slack (всегда)
│  └─ Условие: нет
│  └─ Маппинг: уведомление в канал
│
├─ Выход 2: PagerDuty (только критичные)
│  └─ Условие: {{severity}} == "critical"
│  └─ Маппинг: создать инцидент
│
└─ Выход 3: Jira (только ошибки)
   └─ Условие: {{type}} == "error"
   └─ Маппинг: создать тикет
```

### Пример 3: Синхронизация данных

Webhook о изменении пользователя синхронизирует данные:

```
Webhook: обновление пользователя
├─ Выход 1: CRM
│  └─ Маппинг: обновить контакт
│  └─ Target: https://crm.example.com/api/contacts
│
├─ Выход 2: Marketing Platform
│  └─ Маппинг: обновить подписчика
│  └─ Target: https://marketing.example.com/api/subscribers
│
└─ Выход 3: Analytics
   └─ Маппинг: обновить профиль
   └─ Target: https://analytics.example.com/api/profiles
```

## Настройка приоритета

Приоритет определяет порядок выполнения выходов:

- **0** - самый высокий приоритет (выполняется первым)
- **1, 2, 3...** - выполняются по возрастанию
- Выходы с одинаковым приоритетом выполняются параллельно

**Пример:**
```
Priority 0: Критичные системы (CRM, Database)
Priority 1: Аналитика и отчеты
Priority 2: Уведомления (Email, Slack)
Priority 3: Второстепенные системы
```

## Условное выполнение

**Статус:** В разработке

Условия позволяют выполнять выход только при определенных условиях:

```
{{event_type}} == "user.created"
{{amount}} > 1000
{{status}} in ["pending", "processing"]
```

**Текущее поведение:** Поле для условия доступно в UI, но пока все выходы выполняются всегда. Полноценный парсер условий будет добавлен в следующих версиях.

## Обработка ошибок

- Каждый выход обрабатывается независимо
- Ошибка в одном выходе не останавливает другие
- Все ошибки логируются с указанием выхода
- Можно отключить проблемный выход без остановки интеграции

## Тестирование

Перед активацией выхода рекомендуется:

1. Настроить маппинг
2. Нажать "Протестировать" на странице настройки маппинга
3. Проверить результат трансформации
4. Убедиться, что данные корректны
5. Сохранить и включить выход

## Производительность

- Выходы выполняются параллельно через goroutines
- Нет блокировки при выполнении одного выхода
- Оптимально для большого количества выходов
- Рекомендуется не более 10-15 выходов на одну интеграцию

## Ограничения

- Условное выполнение пока не реализовано полностью
- Нет retry механизма для отдельных выходов (планируется)
- Нет последовательного выполнения (только параллельное)

## Миграция с основного маппинга

Если у вас уже есть интеграция с настроенным маппингом:

1. Создайте первый выход с теми же настройками
2. Скопируйте маппинг из основной интеграции
3. Протестируйте выход
4. Создайте дополнительные выходы по необходимости
5. Основной маппинг интеграции больше не будет использоваться

## FAQ

**Q: Можно ли использовать и основной маппинг, и выходы одновременно?**
A: Нет. Если у интеграции есть хотя бы один выход, используются только выходы. Основной маппинг игнорируется.

**Q: Как отключить выход временно?**
A: Используйте кнопку "Выключить" на странице управления выходами. Выход останется в списке, но не будет выполняться.

**Q: Можно ли копировать маппинг между выходами?**
A: Пока нет, но эта функция планируется. Сейчас нужно настраивать каждый выход отдельно.

**Q: Что происходит, если все выходы отключены?**
A: Webhook будет принят, но данные никуда не отправятся. Интеграция останется активной.

**Q: Можно ли использовать разные форматы для разных выходов?**
A: Да! Каждый выход может иметь свой тип шаблона (JSON, XML, Text, Custom).
