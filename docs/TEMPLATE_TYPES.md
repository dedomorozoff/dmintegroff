# Типы шаблонов трансформации данных

## Обзор

dmIntegroff поддерживает различные типы шаблонов для трансформации данных, что позволяет отправлять данные не только в формате JSON, но и в других форматах.

## Доступные типы шаблонов

### 1. JSON (по умолчанию)

**Content-Type:** `application/json`

Стандартный формат для API интеграций. Поддерживает полную валидацию структуры.

**Пример:**
```json
{
  "user": {
    "name": "{{user.name}}",
    "email": "{{user.email}}"
  },
  "timestamp": "{{timestamp}}",
  "custom_field": "статическое значение"
}
```

**Особенности:**
- Автоматическая валидация JSON структуры
- Поддержка вложенных объектов
- Правильная обработка типов данных (строки в кавычках, числа без кавычек)

### 2. XML

**Content-Type:** `application/xml`

Формат для интеграции с системами, использующими XML.

**Пример:**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <user>
    <name>{{user.name}}</name>
    <email>{{user.email}}</email>
  </user>
  <timestamp>{{timestamp}}</timestamp>
  <custom_field>статическое значение</custom_field>
</root>
```

**Особенности:**
- Автоматическое экранирование специальных символов XML
- Поддержка атрибутов с плейсхолдерами
- Декларация XML включается автоматически

### 3. Plain Text

**Content-Type:** `text/plain`

Простой текстовый формат для логов, уведомлений или простых API.

**Пример:**
```
Пользователь: {{user.name}}
Email: {{user.email}}
Время: {{timestamp}}

Дополнительная информация:
{{description}}
```

**Особенности:**
- Свободный формат текста
- Сохранение переносов строк
- Идеально для email уведомлений или логов

### 4. Custom (Произвольный формат)

**Content-Type:** `text/plain`

Полная свобода для создания любого формата данных.

**Примеры использования:**

**CSV:**
```
{{user.name}},{{user.email}},{{timestamp}}
```

**TSV:**
```
{{user.name}}	{{user.email}}	{{timestamp}}
```

**Custom Protocol:**
```
USER:{{user.name}}|EMAIL:{{user.email}}|TIME:{{timestamp}}
```

**Configuration File:**
```
[user]
name = {{user.name}}
email = {{user.email}}

[metadata]
timestamp = {{timestamp}}
```

## Синтаксис плейсхолдеров

Все типы шаблонов используют единый синтаксис плейсхолдеров:

### Базовый синтаксис
```
{{field.path}}
```

### Вложенные поля
```
{{user.address.city}}
```

### Элементы массива
```
{{items[0].name}}
```

### Весь массив (wildcard)
```
{{items.*}}
```
Копирует массив целиком в JSON формате.

## Выбор типа шаблона

При настройке трансформации данных:

1. Переключитесь на режим "Кастомный шаблон"
2. Выберите тип шаблона из выпадающего списка
3. Введите шаблон в соответствующем формате
4. Используйте кнопку "Проверить шаблон" для валидации

## Автоматическая установка Content-Type

Система автоматически устанавливает правильный Content-Type заголовок при отправке данных:

- **JSON:** `application/json`
- **XML:** `application/xml`
- **Text:** `text/plain`
- **Custom:** `text/plain` (можно переопределить через Custom Headers)

## Примеры использования

### Интеграция с XML API

```xml
<?xml version="1.0" encoding="UTF-8"?>
<order>
  <customer>
    <id>{{customer.id}}</id>
    <name>{{customer.name}}</name>
  </customer>
  <items>{{items.*}}</items>
  <total>{{order.total}}</total>
</order>
```

### Email уведомление (Plain Text)

```
Новый заказ от {{customer.name}}

Email: {{customer.email}}
Телефон: {{customer.phone}}

Товары:
{{order.items_description}}

Итого: {{order.total}} руб.

Время заказа: {{timestamp}}
```

### CSV экспорт (Custom)

```
"{{order.id}}","{{customer.name}}","{{customer.email}}","{{order.total}}","{{timestamp}}"
```

## Миграция с JSON на другие форматы

Если у вас уже настроен JSON шаблон и вы хотите перейти на другой формат:

1. Откройте настройку трансформации интеграции
2. Выберите новый тип шаблона
3. Скопируйте существующие плейсхолдеры
4. Адаптируйте их под новый формат
5. Сохраните изменения

## Обратная совместимость

Все существующие интеграции с JSON шаблонами продолжат работать без изменений. Поле `template_type` автоматически устанавливается в `json` для существующих интеграций.

## Ограничения

- Для JSON шаблонов выполняется валидация структуры
- Для других типов валидация ограничена проверкой наличия плейсхолдеров
- Кнопка "Автоотступы" доступна только для JSON шаблонов
- Wildcard `{{field.*}}` работает для всех типов, но возвращает JSON представление массива

## Советы

1. **Используйте JSON** для большинства REST API интеграций
2. **Используйте XML** для SOAP или legacy систем
3. **Используйте Plain Text** для логов, уведомлений, простых webhook
4. **Используйте Custom** для специфических протоколов или форматов данных
