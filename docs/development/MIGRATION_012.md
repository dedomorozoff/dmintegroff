# Миграция 012: Типы шаблонов трансформации

## Обзор

Миграция 012 добавляет поддержку различных типов шаблонов трансформации данных (JSON, XML, Plain Text, Custom).

## Что изменилось

### База данных
- Добавлено поле `template_type` в таблицу `integrations`
- Тип: VARCHAR(50) / TEXT
- Значение по умолчанию: `'json'`
- Возможные значения: `json`, `xml`, `text`, `custom`

### Функциональность
- Автоматическая установка Content-Type на основе типа шаблона
- Поддержка не-JSON форматов данных
- Улучшенное отображение в логах

## Применение миграции

### Автоматически (рекомендуется)

```bash
# Windows
dmintegroff.exe -migrate

# Linux/Mac
./dmintegroff -migrate
```

### Вручную

#### SQLite
```bash
sqlite3 dmintegroff.db < migrations/012_add_template_type_sqlite.sql
```

#### MySQL/PostgreSQL
```bash
mysql -u username -p database_name < migrations/012_add_template_type.sql
```

## Обратная совместимость

✅ **Полная обратная совместимость**

- Все существующие интеграции продолжат работать без изменений
- Поле `template_type` автоматически устанавливается в `'json'` для существующих записей
- Старые JSON шаблоны работают как раньше

## Проверка после миграции

### 1. Проверка структуры БД

#### SQLite
```bash
sqlite3 dmintegroff.db "PRAGMA table_info(integrations);"
```

Должно быть поле `template_type` с типом TEXT и значением по умолчанию 'json'.

#### MySQL
```sql
DESCRIBE integrations;
```

### 2. Проверка данных

```sql
-- Проверяем, что все существующие интеграции имеют template_type = 'json'
SELECT id, name, template_type FROM integrations;
```

### 3. Функциональная проверка

1. Откройте существующую интеграцию с JSON шаблоном
2. Убедитесь, что она работает как раньше
3. Создайте новую интеграцию с XML шаблоном
4. Проверьте логи - Content-Type должен быть `application/xml`

## Новые возможности

### 1. Выбор типа шаблона

При настройке трансформации данных:
- Переключитесь на "Кастомный шаблон"
- Выберите тип из выпадающего списка
- Введите шаблон в соответствующем формате

### 2. Автоматический Content-Type

Система автоматически устанавливает:
- `application/json` для JSON
- `application/xml` для XML
- `text/plain` для Text и Custom

### 3. Улучшенные логи

В разделе "Тесты интеграций":
- Content-Type отображается цветным бейджем
- JSON данные подсвечиваются
- Не-JSON данные отображаются корректно
- Content-Type выделен в заголовках

## Примеры использования

### JSON (по умолчанию)
```json
{
  "user": "{{user.name}}",
  "email": "{{user.email}}"
}
```

### XML
```xml
<?xml version="1.0" encoding="UTF-8"?>
<user>
  <name>{{user.name}}</name>
  <email>{{user.email}}</email>
</user>
```

### Plain Text
```
Пользователь: {{user.name}}
Email: {{user.email}}
```

### Custom (CSV)
```
{{user.name}},{{user.email}},{{timestamp}}
```

## Откат миграции

⚠️ **Внимание:** Откат приведет к потере информации о типах шаблонов!

### SQLite
```sql
-- Создаем резервную копию
.backup backup.db

-- Удаляем поле (требует пересоздания таблицы)
```

```sql

mysqldump -u username -p database_name > backup.sql

-- Удаляем поле
ALTER TABLE integrations DROP COLUMN template_type;
```

## Известные ограничения

1. **Валидация:**
   - Для JSON выполняется полная валидация структуры
   - Для других типов валидация ограничена

2. **Автоотступы:**
   - Кнопка "Автоотступы" доступна только для JSON

3. **Wildcard массивов:**
   - `{{field.*}}` возвращает JSON представление массива
   - Работает для всех типов шаблонов
