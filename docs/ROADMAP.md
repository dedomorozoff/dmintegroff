### 🔥 Высокий приоритет

#### 1. 🚀 AI-ассистент для создания интеграций
**Описание:** Революционная функция автоматического создания интеграций с помощью искусственного интеллекта. Пользователь описывает что хочет сделать на естественном языке, AI анализирует входящие данные и автоматически создает маппинг для целевого API.

**Статус:** 📋 Запланировано (Приоритет #1)

**Планируемая реализация:**

**1.1. AI-чат интерфейс**
- 📋 Встроенный чат-бот на странице создания интеграции
- 📋 Поддержка естественного языка (русский/английский)
- 📋 Контекстное понимание задач интеграции
- 📋 Пошаговые вопросы для уточнения требований

**1.2. Автоматический анализ данных**
- 📋 AI анализирует структуру входящих данных (JSON, XML, form-data)
- 📋 Определение типов полей и их назначения
- 📋 Предложение оптимальной структуры маппинга
- 📋 Автоматическое создание шаблонов трансформации

**1.3. Интеграция с популярными API**
- 📋 База знаний популярных API (Slack, Telegram, CRM системы)
- 📋 Автоматическое создание правильных запросов для известных сервисов
- 📋 Предустановленные шаблоны аутентификации
- 📋 Валидация совместимости с целевыми API

**1.4. Умное предложение маппинга**
- 📋 AI предлагает соответствие полей входящих данных и целевого API
- 📋 Автоматическое создание трансформаций (форматирование дат, конвертация типов)
- 📋 Предложение условной логики и фильтров
- 📋 Оптимизация производительности маппинга

**1.5. Интерактивное обучение**
- 📋 AI учится на примерах пользователя
- 📋 Улучшение предложений на основе обратной связи
- 📋 Сохранение успешных паттернов для будущих интеграций
- 📋 Персонализированные рекомендации

**Примеры использования:**

**Пример 1: Простая задача**
```
Пользователь: "Хочу отправлять уведомления в Slack когда приходит новый заказ"

AI анализирует:
- Входящие данные: заказ (JSON с полями order_id, customer, amount)
- Целевой API: Slack webhook
- Создает маппинг: форматирует сообщение с деталями заказа
- Настраивает аутентификацию и URL
```

**Пример 2: Сложная задача**
```
Пользователь: "Нужно синхронизировать данные клиентов из CRM в аналитику, но только активных клиентов с суммой заказов больше 1000"

AI создает:
- Условие: customer.status == "active" && customer.total_orders > 1000
- Маппинг полей CRM → Analytics API
- Трансформацию данных (форматы дат, валюты)
- Настройку аутентификации для обеих систем
```

**Пример 3: Множественные выходы**
```
Пользователь: "При новой заявке отправить в CRM, уведомить менеджера в Telegram и создать задачу в Jira"

AI создает 3 выхода:
1. CRM: маппинг заявки в лид
2. Telegram: форматированное уведомление
3. Jira: создание задачи с правильными полями
```

**Технические требования:**
- 📋 Интеграция с OpenAI API или локальной LLM
- 📋 База знаний API документации популярных сервисов
- 📋 Система промптов для разных типов задач
- 📋 Валидация и тестирование сгенерированных маппингов
- 📋 Откат к ручной настройке при необходимости

**Польза:**
- 🚀 Революционное упрощение создания интеграций
- ⚡ Сокращение времени настройки с часов до минут
- 🎯 Снижение порога входа для нетехнических пользователей
- 🧠 Автоматическое применение лучших практик
- 📈 Масштабируемость решения для любых API

**Планируемые этапы:**
1. 📋 MVP: базовый AI-чат с простыми шаблонами
2. 📋 Анализ данных и автоматическое создание маппинга
3. 📋 База знаний популярных API
4. 📋 Обучение на пользовательских данных
5. 📋 Продвинутая логика и условия

#### 3. ✅ Поддержка различных форматов входящих данных
**Описание:** Расширить возможности приема данных - не только JSON, но и form-data, XML, и другие форматы.

**Статус:** ✅ Реализовано (8 декабря 2024)

**Реализация:**

**2.1. Form-data (application/x-www-form-urlencoded, multipart/form-data)**
- ✅ Автоматическое определение Content-Type
- ✅ Парсинг form-data в структуру данных
- ✅ Преобразование в JSON для маппинга
- ✅ Поддержка файлов (сохранение метаданных в поле `_files`)
- ✅ Обработка множественных значений для одного ключа

**2.2. XML (application/xml, text/xml)**
- ✅ Парсинг XML в структуру данных
- ✅ Преобразование в JSON для маппинга
- ✅ Сохранение атрибутов (с суффиксом `_attributes`)
- ✅ Обработка вложенных элементов

**2.3. Plain Text**
- ✅ Обработка как строкового значения в поле `text`
- ✅ Автоматическое разбиение на строки (поле `lines`)
- ✅ Подсчет длины и количества строк

**2.4. Автоопределение формата**
- ✅ Определение по Content-Type заголовку
- ✅ Fallback на JSON при неизвестном формате
- ✅ Попытка определения формата по содержимому

**2.5. Ручное редактирование в разных форматах**
- ✅ Выбор формата в UI редактора образца (JSON, XML, Form-data, Text)
- ✅ Автоматическая конвертация в JSON при сохранении
- ✅ Валидация для каждого формата
- ✅ Placeholder с примерами для каждого формата
- ✅ Кнопка "Конвертировать в JSON" для предпросмотра

**Польза:**
- Универсальность системы - поддержка любых источников данных
- Интеграция с legacy системами (XML, form-data)
- Гибкость в приеме данных
- Единообразная обработка через JSON маппинг

**Изменённые файлы:**
- `internal/utils/format_parser.go` - новый файл с парсерами форматов
- `internal/controllers/integration_controller.go` - обновлен `WebhookHandler`
- Добавлены импорты `mime/multipart` и `net/url`

**Технические детали:**
- Все форматы конвертируются в `map[string]interface{}` для единообразной обработки
- Для form-data и XML создается JSON представление
- Файлы в multipart/form-data сохраняются как метаданные
- Поддержка до 32 MB для multipart форм

**Примеры использования:**

**JSON (как раньше):**
```json
{
  "user": "John",
  "email": "john@example.com"
}
```

**Form-data:**
```
POST /webhook/token
Content-Type: application/x-www-form-urlencoded

user=John&email=john@example.com
```
Преобразуется в:
```json
{
  "user": "John",
  "email": "john@example.com"
}
```

**XML:**
```xml
<?xml version="1.0"?>
<user>
  <name>John</name>
  <email>john@example.com</email>
</user>
```
Преобразуется в:
```json
{
  "name": "John",
  "email": "john@example.com"
}
```

**Plain Text:**
```
Hello World
This is a test
```
Преобразуется в:
```json
{
  "text": "Hello World\nThis is a test",
  "lines": ["Hello World", "This is a test"],
  "line_count": 2,
  "length": 25
}
```

#### 5. ✅ Множественные маппинги на один webhook
**Описание:** Возможность настроить несколько маппингов (трансформаций) для одного входящего webhook с отправкой на разные Target API.

**Статус:** ✅ Реализовано (9 декабря 2024)

**Реализация:**

**4.1. Архитектура**
- ✅ Один webhook может иметь несколько "выходов" (outputs)
- ✅ Каждый выход имеет свой Target API и маппинг
- ✅ Выходы выполняются параллельно (через goroutines)
- ✅ Независимая обработка ошибок для каждого выхода

**4.2. UI для управления выходами**
- ✅ Список выходов на странице `/integrations/:id/outputs`
- ✅ Кнопка "Управление выходами" в меню интеграции
- ✅ Кнопка "Добавить выход" для создания нового маппинга
- ✅ Каждый выход имеет:
  - ✅ Название и описание (для идентификации)
  - ✅ Target API URL
  - ✅ HTTP метод
  - ✅ Аутентификация (OAuth, Bearer, Basic)
  - ✅ Маппинг/шаблон (JSON, XML, Text, Custom)
  - ✅ Условия выполнения (поле готово, логика в разработке)
  - ✅ Приоритет/порядок выполнения

**4.3. Настройка маппинга для каждого выхода**
- ✅ Отдельная страница настройки для каждого выхода
- ✅ Использование одного `SamplePayload` для всех выходов
- ✅ Поддержка шаблонов и простого маппинга
- ✅ Кнопка "Протестировать" для предпросмотра результата

**4.4. Условное выполнение**
- ✅ Поле для условия в UI
- 🔄 Парсер условий (пока заглушка, выполняются все выходы)
- 📋 Планируется: полноценный парсер выражений

**4.5. Обработка ошибок**
- ✅ Независимая обработка для каждого выхода
- ✅ Если один выход упал - остальные продолжают работать
- ✅ Логирование ошибок с указанием выхода
- 📋 Планируется: Retry механизм для каждого выхода отдельно

**Польза:**
- Один webhook → несколько систем (например: CRM + Analytics + Notification)
- Разные форматы данных для разных систем
- Экономия ресурсов (не нужно создавать несколько интеграций)
- Централизованное управление обработкой webhook

**Примеры использования:**

**Пример 1: E-commerce заказ**
```
Webhook: новый заказ
├─ Выход 1: CRM (Salesforce)
│  └─ Маппинг: создать лид
├─ Выход 2: Analytics (Google Analytics)
│  └─ Маппинг: отправить событие покупки
├─ Выход 3: Email (SendGrid)
│  └─ Маппинг: отправить подтверждение заказа
└─ Выход 4: Warehouse (внутренняя система)
   └─ Маппинг: создать задачу на отгрузку
```

**Пример 2: Условное выполнение**
```
Webhook: событие пользователя
├─ Выход 1: Slack (всегда)
│  └─ Условие: нет
│  └─ Маппинг: уведомление о событии
├─ Выход 2: PagerDuty (только критичные)
│  └─ Условие: {{severity}} == "critical"
│  └─ Маппинг: создать инцидент
└─ Выход 3: Jira (только ошибки)
   └─ Условие: {{type}} == "error"
   └─ Маппинг: создать тикет
```

**Изменённые/созданные файлы:**
- ✅ `internal/models/integration_output.go` - новая модель `IntegrationOutput`
- ✅ `internal/controllers/integration_output_controller.go` - контроллер для управления выходами
- ✅ `internal/services/output_processor.go` - параллельная обработка выходов
- ✅ `internal/controllers/integration_controller.go` - обновлен WebhookHandler
- ✅ `templates/pages/integration_outputs.html` - список выходов
- ✅ `templates/pages/integration_output_create.html` - форма создания выхода
- ✅ `templates/pages/integration_output_configure.html` - настройка маппинга выхода
- ✅ `templates/pages/integration_output_edit.html` - редактирование выхода
- ✅ `templates/pages/integrations.html` - добавлена кнопка "Управление выходами"
- ✅ `migrations/007_create_integration_outputs.sql` - миграция БД
- ✅ `cmd/server/main.go` и `cmd/admin/main.go` - добавлена автомиграция

**Реализованные API endpoints:**
```
GET    /integrations/:id/outputs                      - список выходов
GET    /integrations/:id/outputs/create               - форма создания выхода
POST   /integrations/:id/outputs                      - создать выход
GET    /integrations/:id/outputs/:output_id/configure - настройка маппинга выхода
POST   /integrations/:id/outputs/:output_id/configure - сохранить маппинг выхода
GET    /integrations/:id/outputs/:output_id/edit      - форма редактирования выхода
POST   /integrations/:id/outputs/:output_id/update    - обновить выход
POST   /integrations/:id/outputs/:output_id/delete    - удалить выход
POST   /integrations/:id/outputs/:output_id/toggle    - включить/выключить выход
POST   /integrations/:id/outputs/:output_id/test      - протестировать выход
```

**Технические детали:**
- Выходы выполняются параллельно через goroutines с использованием sync.WaitGroup
- Каждый выход имеет независимую аутентификацию и настройки
- Поддержка всех типов шаблонов (JSON, XML, Text, Custom)
- Обратная совместимость: если выходов нет, используется основной маппинг интеграции
- Логирование всех операций с выходами
