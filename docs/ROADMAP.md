## 📋 Запланированные функции

### 🔥 Высокий приоритет

#### 1. Использование запроса в качестве образца данных в тестовом хуке
**Описание:** В тестовом webhook endpoint добавить возможность использовать полученный запрос как образец данных для настройки маппинга.

**Текущее состояние:** Тестовый хук принимает запросы, но не сохраняет их как образец для интеграции.

**Планируемая реализация:**
- Добавить кнопку "Использовать как образец" в интерфейсе тестового хука
- При нажатии - сохранить запрос в `SamplePayload` выбранной интеграции
- Автоматически перенаправить на страницу настройки маппинга

**Польза:**
- Упрощение тестирования интеграций
- Возможность быстро создать маппинг на основе тестовых данных
- Удобство при разработке и отладке

**Файлы для изменения:**
- `internal/controllers/webhook_test_controller.go`
- `templates/pages/webhook_test.html`
- Добавить новый endpoint: `POST /api/webhook-test/:token/use-as-sample`

#### 2. Поддержка различных форматов входящих данных
**Описание:** Расширить возможности приема данных - не только JSON, но и form-data, XML, и другие форматы.

**Текущее состояние:** Система принимает только JSON данные.

**Планируемая реализация:**

**2.1. Form-data (application/x-www-form-urlencoded, multipart/form-data)**
- Автоматическое определение Content-Type
- Парсинг form-data в структуру данных
- Преобразование в JSON для маппинга
- Поддержка файлов (сохранение метаданных)

**2.2. XML (application/xml, text/xml)**
- Парсинг XML в структуру данных
- Преобразование в JSON для маппинга
- Сохранение атрибутов и пространств имен
- Поддержка CDATA секций

**2.3. Plain Text**
- Обработка как строкового значения
- Возможность применения регулярных выражений для извлечения данных

**2.4. Binary данные**
- Сохранение метаданных (размер, тип, имя файла)
- Опциональное сохранение в файловую систему или S3

**Польза:**
- Универсальность системы
- Поддержка большего количества источников данных
- Интеграция с legacy системами

**Файлы для изменения:**
- `internal/controllers/integration_controller.go` - функция `WebhookHandler`
- `internal/utils/parser.go` - новый файл для парсинга различных форматов
- `internal/models/integration.go` - добавить поле `InputFormat`
- `templates/pages/integration_configure.html` - UI для выбора формата

**Пример использования:**
```go
// Определение формата по Content-Type
contentType := c.GetHeader("Content-Type")
switch {
case strings.Contains(contentType, "application/json"):
    // JSON парсинг (текущая реализация)
case strings.Contains(contentType, "application/x-www-form-urlencoded"):
    // Form-data парсинг
case strings.Contains(contentType, "application/xml"):
    // XML парсинг
case strings.Contains(contentType, "text/plain"):
    // Plain text обработка
}
```

#### 3. Тестирование запроса после настройки маппинга
**Описание:** Добавить возможность протестировать настроенный маппинг прямо из интерфейса настройки.

**Текущее состояние:** Для тестирования нужно активировать интеграцию и отправить реальный запрос.

**Планируемая реализация:**

**3.1. Кнопка "Протестировать запрос"**
- Расположение: после секции "Настройка трансформации данных"
- Действие: отправить тестовый запрос с текущим маппингом
- Использовать `SamplePayload` как входные данные
- Показать результат трансформации

**3.2. Модальное окно с результатами**
- Входные данные (SamplePayload)
- Примененный маппинг/шаблон
- Результат трансформации
- Статус отправки на Target API (если включено)
- Ошибки (если есть)

**3.3. Кнопка "Посмотреть в тесте интеграций"**
- Появляется после успешного теста
- Перенаправляет на страницу тестового webhook
- Показывает детали последнего тестового запроса

**Польза:**
- Быстрая проверка маппинга без активации интеграции
- Отладка трансформаций
- Уверенность в корректности настроек перед активацией

**Файлы для изменения:**
- `templates/pages/integration_configure.html` - добавить кнопку и модальное окно
- `internal/controllers/integration_controller.go` - новая функция `IntegrationTestMapping`
- Добавить новый endpoint: `POST /api/integrations/:id/test-mapping`

**Пример UI:**
```html
<div style="margin-top: 2rem;">
    <button type="button" class="btn btn-primary" onclick="testMapping()">
        <i data-lucide="play-circle"></i> Протестировать запрос
    </button>
</div>

<!-- Модальное окно с результатами -->
<div id="testResultModal" style="display: none;">
    <h3>Результаты тестирования</h3>
    <div class="test-result">
        <h4>Входные данные:</h4>
        <pre id="testInput"></pre>
        
        <h4>Результат трансформации:</h4>
        <pre id="testOutput"></pre>
        
        <h4>Статус отправки:</h4>
        <div id="testStatus"></div>
    </div>
    
    <button class="btn btn-secondary" onclick="viewInWebhookTest()">
        <i data-lucide="external-link"></i> Посмотреть в тесте интеграций
    </button>
</div>
```

#### 4. Исправление бага в редакторе образца данных
**Описание:** Исправить баг, который возникает при редактировании образца данных без предварительного получения webhook.

**Текущее состояние:** При попытке редактировать пустой образец или создать его вручную возникают ошибки.

**Проблемы:**
- Редактор не инициализируется корректно для пустого payload
- Валидация JSON не работает должным образом
- Подсветка синтаксиса глючит при вставке данных

**Планируемые исправления:**

**4.1. Инициализация редактора**
- Корректная инициализация для пустого значения
- Placeholder с примером JSON
- Автоматическое форматирование при вставке

**4.2. Валидация**
- Проверка JSON перед сохранением
- Понятные сообщения об ошибках
- Подсветка строки с ошибкой

**4.3. Подсветка синтаксиса**
- Исправить баг с вставкой HTML-мусора
- Улучшить обработку paste событий
- Корректная работа с кавычками

**Файлы для изменения:**
- `templates/pages/integration_configure.html` - JavaScript код редактора
- `static/js/json-highlight.js` - логика подсветки синтаксиса

**Тестовые сценарии:**
1. Создать интеграцию без получения webhook
2. Открыть страницу настройки маппинга
3. Нажать "Редактировать JSON"
4. Вставить JSON из буфера обмена
5. Проверить корректность отображения и сохранения

## 💡 Идеи для будущего
