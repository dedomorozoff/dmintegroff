# Тестирование произвольных заголовков

## Что реализовано:

1. **Модель данных** - добавлено поле `CustomHeaders` в `models.Integration`
2. **Миграция** - `011_add_custom_headers.sql` и `011_add_custom_headers_sqlite.sql`
3. **UI формы создания** - секция "Произвольные заголовки" в `integration_create.html`
4. **UI формы редактирования** - секция "Произвольные заголовки" в `integration_edit.html`
5. **Контроллер** - обработка `custom_headers` в создании и обновлении интеграции
6. **Сервис** - функция `AddCustomHeaders()` в `oauth_service.go`
7. **Применение** - заголовки добавляются в:
   - REST API запросы (`integration_service.go`)
   - GraphQL запросы (`graphql_service.go`)

## Логирование для отладки:

1. **Логирование в контроллере** - при создании/обновлении интеграции логируется значение `custom_headers`
2. **Логирование в сервисе** - функция `AddCustomHeaders` логирует:
   - Когда заголовки отсутствуют
   - Сырые данные перед парсингом
   - Каждый добавленный заголовок
   - Общее количество примененных заголовков
3. **Логирование перед отправкой** - все заголовки HTTP запроса логируются перед отправкой

## Как использовать:

1. Откройте форму создания/редактирования интеграции
2. Найдите секцию "Произвольные заголовки"
3. Нажмите "Добавить заголовок"
4. Введите имя заголовка (например: `X-API-Key`)
5. Введите значение (например: `your-secret-key`)
6. Можно добавить несколько заголовков
7. При сохранении они будут применяться ко всем запросам к Target API

## Примеры использования:

- `Content-Type: application/xml` - для XML API
- `X-API-Key: secret123` - для API с ключом
- `Accept: application/vnd.api+json` - для JSON:API
- `User-Agent: MyApp/1.0` - кастомный User-Agent
- `X-Custom-Header: custom-value` - любой произвольный заголовок

## Как проверить:

### 1. Проверка JavaScript (локально)
Откройте `test_form.html` в браузере и проверьте, что JavaScript правильно собирает заголовки в JSON.

### 2. Проверка сохранения в БД

1. Запустите приложение с уровнем логирования `debug`:
   ```bash
   # В .env установите:
   LOG_LEVEL=debug
   GIN_MODE=debug
   ```

2. Создайте новую интеграцию с произвольными заголовками:
   - Откройте форму создания интеграции
   - Добавьте несколько заголовков (например: `X-API-Key: test123`)
   - Сохраните

3. Проверьте логи - должны быть записи:
   ```
   INFO Creating integration with custom headers custom_headers={"X-API-Key":"test123"}
   ```

### 3. Проверка применения заголовков

1. Отправьте тестовый webhook на интеграцию
2. Проверьте логи - должны быть записи:
   ```
   DEBUG Processing custom headers custom_headers_raw={"X-API-Key":"test123"}
   DEBUG Added custom header header=X-API-Key value=test123
   INFO Custom headers applied count=1
   DEBUG Request headers before sending headers=map[Content-Type:[application/json] X-Api-Key:[test123] ...]
   ```

### 4. Проверка в логах запросов

Откройте страницу логов интеграции и проверьте:
- Request Headers должны содержать ваши кастомные заголовки
- Если есть ошибки, они будут в ErrorMessage

## Возможные проблемы:

### Заголовки не сохраняются в БД
- Проверьте, что JavaScript выполняется перед отправкой формы
- Откройте DevTools → Network → посмотрите POST запрос → Form Data → должно быть поле `custom_headers` с JSON

### Заголовки сохраняются, но не применяются
- Проверьте логи на наличие ошибок парсинга JSON
- Убедитесь, что JSON валидный (не пустой, правильный формат)

### Заголовки применяются, но не видны в целевом API
- Проверьте логи "Request headers before sending" - заголовки должны быть там
- Некоторые заголовки могут быть перезаписаны (например, Content-Type)
- Проверьте, что целевой API действительно получает запрос

## Технические детали:

- Заголовки хранятся в БД как JSON строка
- При отправке запроса парсятся и добавляются через `req.Header.Set()`
- Применяются после аутентификации, но перед отправкой запроса
- Работают для REST, GraphQL и GraphQL enrichment запросов
