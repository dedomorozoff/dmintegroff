# Тестирование функции "Использовать как образец данных"

## Описание
Тестирование новой функции, которая позволяет использовать запрос из тестового webhook в качестве образца данных для интеграции.

## Предварительные требования
1. Запущенное приложение dmIntegroff
2. Авторизованный пользователь
3. Хотя бы одна созданная интеграция

## Шаги тестирования

### 1. Создание тестового webhook
1. Перейти на дашборд
2. Нажать кнопку "Создать тестовый вебхук"
3. Скопировать URL тестового webhook
4. Убедиться, что открылась страница с деталями webhook

### 2. Отправка тестового запроса
Отправить POST запрос на URL тестового webhook с JSON данными:

```bash
curl -X POST "http://localhost:8080/webhook/test/YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "event": "user.created",
    "user": {
      "id": 123,
      "name": "John Doe",
      "email": "john@example.com"
    },
    "timestamp": "2024-12-08T10:00:00Z"
  }'
```

Или использовать кнопку "Отправить тестовый запрос" на странице webhook.

### 3. Использование запроса как образца
1. На странице тестового webhook найти полученный запрос
2. Нажать на запрос, чтобы раскрыть детали
3. Нажать кнопку "Использовать как образец данных"
4. В модальном окне выбрать интеграцию из списка
5. Нажать на интеграцию

### 4. Проверка результата
1. Должно появиться уведомление "Образец данных сохранён"
2. Произойдет автоматический редирект на страницу настройки маппинга выбранной интеграции
3. В поле "Образец данных" должен отображаться JSON из тестового запроса
4. Можно сразу начать настройку маппинга на основе этих данных

## Ожидаемые результаты

### Успешный сценарий
- ✅ Модальное окно открывается и показывает список интеграций
- ✅ При клике на интеграцию данные сохраняются
- ✅ Происходит редирект на страницу настройки маппинга
- ✅ Образец данных корректно отображается в интеграции

### Граничные случаи
- ✅ Если нет интеграций - показывается сообщение с кнопкой создания
- ✅ Если запрос не содержит body - кнопка все равно работает (сохраняет пустое значение)
- ✅ Модальное окно закрывается при клике вне его области
- ✅ Модальное окно закрывается при клике на кнопку X

### Ошибки
- ❌ Если webhook не принадлежит пользователю - 404 ошибка
- ❌ Если запрос не найден - 404 ошибка
- ❌ Если интеграция не принадлежит пользователю - 404 ошибка
- ❌ Если не передан integration_id - 400 ошибка

## API Endpoint

```
POST /api/webhook-test/:token/use-as-sample/:request_id
```

### Request Body
```json
{
  "integration_id": 1
}
```

### Response (Success)
```json
{
  "status": "success",
  "message": "Request saved as sample payload",
  "integration_id": 1,
  "redirect_url": "/integrations/1/configure"
}
```

### Response (Error)
```json
{
  "error": "Webhook not found"
}
```

## Проверка в базе данных

После успешного сохранения можно проверить в БД:

```sql
SELECT id, name, sample_payload 
FROM integrations 
WHERE id = YOUR_INTEGRATION_ID;
```

Поле `sample_payload` должно содержать JSON из тестового запроса.

## Примечания

- Функция работает только для запросов, принадлежащих текущему пользователю
- Можно использовать один и тот же запрос для нескольких интеграций
- При повторном использовании образец данных перезаписывается
- Функция работает как с Redis, так и с database storage
