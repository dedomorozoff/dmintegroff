# FAQ - Демо-режим

## Общие вопросы

### Что такое демо-режим?
Демо-режим позволяет автоматически создавать временных пользователей через GET-параметры на странице логина. Это удобно для демонстраций, тестирования и предоставления временного доступа без ручной регистрации.

### Зачем нужен демо-режим?
- Быстрая демонстрация системы потенциальным клиентам
- Автоматизированное тестирование
- Временный доступ для партнеров
- Обучение и тренинги

### Безопасен ли демо-режим?
Да, при правильной настройке:
- Требуется секретный ключ для регистрации
- Демо-пользователи имеют ограниченные права (specialist)
- Вебхуки ограничены разрешенным URL
- Автоматическое удаление через 24 часа

## Настройка

### Как включить демо-режим?
Добавьте в `.env`:
```env
DEMO_MODE=true
DEMO_SECRET=your-secret-key
DEMO_TARGET_URL=https://webhook.site/your-id
```

### Что такое DEMO_SECRET?
Секретный ключ, который нужно передать в GET-параметре `demo_key` для регистрации. Без правильного ключа регистрация не произойдет.

### Что такое DEMO_TARGET_URL?
URL, на который демо-пользователи могут отправлять вебхуки. Это ограничение предотвращает отправку запросов на произвольные адреса.

### Можно ли использовать несколько DEMO_TARGET_URL?
В текущей версии - нет. Поддерживается только один URL. Но вы можете использовать префикс, например `https://webhook.site/` разрешит все URL на этом домене.

## Использование

### Как создать демо-пользователя?
Откройте URL:
```
http://localhost:8080/login?demo_key=YOUR_SECRET&username=demo&password=demo123
```

### Что произойдет после открытия URL?
1. Система проверит секретный ключ
2. Создаст пользователя (или обновит срок действия)
3. Автоматически заполнит поля логина
4. Покажет уведомление об успешной регистрации

### Можно ли использовать любой username?
Да, вы можете использовать любое имя пользователя. Если пользователь с таким именем уже существует, система обновит срок его действия.

### Сколько живут демо-пользователи?
24 часа с момента создания или последнего обновления.

### Когда удаляются демо-пользователи?
Автоматически при заходе любого пользователя на страницу логина. Удаляются только те, у которых истек срок действия.

## Ограничения

### Какие ограничения у демо-пользователей?
1. Роль всегда "specialist" (не admin)
2. Вебхуки можно отправлять только на DEMO_TARGET_URL
3. Автоматическое удаление через 24 часа

### Может ли демо-пользователь стать администратором?
Нет, демо-пользователи всегда создаются с ролью "specialist".

### Можно ли изменить срок действия?
В текущей версии срок фиксирован (24 часа). Для изменения нужно модифицировать код в `RegisterDemoUser()`.

### Что будет, если демо-пользователь попытается отправить вебхук на запрещенный URL?
Вебхук не будет отправлен, и в логах появится ошибка: "demo users can only send webhooks to demo target URL".

## Безопасность

### Можно ли использовать демо-режим в продакшене?
Не рекомендуется. Демо-режим предназначен для тестирования и демонстраций. В продакшене установите `DEMO_MODE=false`.

### Как защитить DEMO_SECRET?
- Используйте длинный случайный ключ
- Не публикуйте его в открытых источниках
- Регулярно меняйте ключ
- Не используйте простые значения типа "demo123"

### Что делать, если DEMO_SECRET скомпрометирован?
1. Измените значение в `.env`
2. Перезапустите сервер
3. Удалите всех демо-пользователей вручную (если нужно)

### Могут ли демо-пользователи видеть данные других пользователей?
Нет, демо-пользователи имеют те же права, что и обычные специалисты. Они видят только свои интеграции.

## Технические вопросы

### Нужно ли применять миграцию?
Да, для работы демо-режима нужны новые поля в таблице users. Выполните:
```bash
go run cmd/admin/main.go
# Выберите "1. Выполнить миграцию базы данных"
```

### Что делать, если миграция не применилась?
Попробуйте вручную:
```bash
# SQLite
sqlite3 dmintegroff.db < migrations/006_add_demo_users_sqlite.sql

# MySQL
mysql -u user -p database < migrations/006_add_demo_users.sql
```

### Как проверить, что демо-режим работает?
1. Откройте URL с параметрами
2. Проверьте, что поля заполнены автоматически
3. Войдите в систему
4. Создайте интеграцию
5. Попробуйте отправить вебхук

### Как посмотреть список демо-пользователей?
```bash
# SQLite
sqlite3 dmintegroff.db "SELECT username, is_demo, expires_at FROM users WHERE is_demo = 1;"

# MySQL
mysql -u user -p -e "SELECT username, is_demo, expires_at FROM users WHERE is_demo = 1;" database
```

### Как вручную удалить демо-пользователей?
```bash
# SQLite
sqlite3 dmintegroff.db "DELETE FROM users WHERE is_demo = 1;"

# MySQL
mysql -u user -p -e "DELETE FROM users WHERE is_demo = 1;" database
```

### Влияет ли демо-режим на производительность?
Минимально. Очистка выполняется только при заходе на страницу логина, и благодаря индексу на `expires_at` работает быстро.

## Отладка

### Демо-пользователь не создается
Проверьте:
1. `DEMO_MODE=true` в `.env`
2. `demo_key` совпадает с `DEMO_SECRET`
3. Миграция применена
4. Сервер перезапущен после изменения `.env`

### Поля логина не заполняются автоматически
Проверьте:
1. URL содержит все параметры: `demo_key`, `username`, `password`
2. `demo_key` правильный
3. Нет ошибок в консоли браузера

### Вебхук не отправляется
Проверьте:
1. `target_api` начинается с `DEMO_TARGET_URL`
2. Пользователь действительно демо (проверьте в БД)
3. Интеграция в режиме "active"
4. Логи сервера на наличие ошибок

### Демо-пользователи не удаляются
Проверьте:
1. Кто-то заходил на `/login` после истечения срока
2. Поле `expires_at` установлено корректно
3. Индекс создан: `CREATE INDEX idx_users_expires_at ON users(expires_at);`

## Примеры

### Пример 1: Демонстрация клиенту
```env
DEMO_MODE=true
DEMO_SECRET=client-demo-2024
DEMO_TARGET_URL=https://webhook.site/abc-123
```

URL для клиента:
```
http://your-server.com/login?demo_key=client-demo-2024&username=client_demo&password=demo2024
```

### Пример 2: Автоматизированное тестирование
```env
DEMO_MODE=true
DEMO_SECRET=test-secret-key
DEMO_TARGET_URL=http://localhost:9000/test-webhook
```

В тестах:
```bash
curl "http://localhost:8080/login?demo_key=test-secret-key&username=test_user_1&password=test123"
```

### Пример 3: Обучение
```env
DEMO_MODE=true
DEMO_SECRET=training-2024
DEMO_TARGET_URL=https://webhook.site/training
```

URL для студентов:
```
http://training.example.com/login?demo_key=training-2024&username=student1&password=student123
```
