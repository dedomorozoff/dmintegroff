# Улучшения отображения логов

## Обзор

Улучшена логика отображения тела запросов и ответов в разделе "Тесты интеграций" с учетом типа контента (Content-Type).

## Что изменилось

### 1. Умное определение типа контента

Система теперь определяет тип контента двумя способами:

#### A. По заголовку Content-Type
```javascript
// Читаем Content-Type из заголовков запроса
const headers = JSON.parse(headersJson);
const contentType = headers['Content-Type'] || headers['content-type'];
```

#### B. По содержимому (fallback)
```javascript
// Если заголовков нет, определяем по содержимому
if (text.startsWith('{') || text.startsWith('[')) {
    // Вероятно JSON
} else if (text.startsWith('<?xml') || text.startsWith('<')) {
    // Вероятно XML
}
```

### 2. Подсветка синтаксиса по типу

#### JSON (`application/json`)
- ✅ Полная подсветка синтаксиса
- ✅ Автоматическое форматирование с отступами
- ✅ Цветовая схема:
  - 🔵 Ключи (синий)
  - 🟢 Строки (зеленый)
  - 🟠 Числа (оранжевый)
  - 🟣 Boolean/null (фиолетовый)

**Пример:**
```json
{
  "user": "Иван",
  "age": 30,
  "active": true
}
```

#### XML (`application/xml`)
- ✅ Базовая подсветка синтаксиса
- ✅ Цветовая схема:
  - 🔴 Имена тегов (красный)
  - 🟠 Атрибуты (оранжевый)
  - 🟢 Значения атрибутов (зеленый)
  - 🟣 XML декларация (фиолетовый)
  - ⚫ Комментарии (серый)

**Пример:**
```xml
<?xml version="1.0"?>
<user>
  <name>Иван</name>
  <age>30</age>
</user>
```

#### Plain Text (`text/plain`)
- ✅ Отображение как есть
- ✅ Перенос длинных строк
- ✅ Сохранение форматирования
- ❌ Без подсветки синтаксиса

**Пример:**
```
Пользователь: Иван
Email: ivan@example.com
Время: 2024-12-06T15:30:00Z
```

#### Custom форматы
- ✅ Отображение как plain text
- ✅ Перенос длинных строк
- ❌ Без подсветки синтаксиса

**Примеры:**
```csv
Иван,ivan@example.com,2024-12-06
```

```
USER:12345|NAME:Иван|EMAIL:ivan@example.com
```

### 3. Безопасная обработка ошибок

```javascript
try {
    const json = JSON.parse(text);
    block.innerHTML = syntaxHighlight(JSON.stringify(json, null, 2));
} catch(e) {
    // Если не удалось распарсить, оставляем как plain text
    console.log('Not valid JSON, displaying as plain text');
}
```

- ❌ Нет ошибок "invalid character"
- ✅ Graceful fallback на plain text
- ✅ Логирование в консоль для отладки

## Визуальные индикаторы

### Content-Type бейдж

Content-Type отображается цветными бейджами в нескольких местах:

#### 1. В заголовке секции "Заголовки запроса"
```
Заголовки запроса [application/json]
                   ↑ синий бейдж
```

#### 2. В заголовке секции "Исходящий запрос к Target API"
```
Исходящий запрос к Target API [application/json]
                               ↑ синий бейдж
```

#### 3. В заголовке секции "Ответ от Target API"
```
Ответ от Target API [application/json]
                     ↑ синий бейдж
```

**Цветовая схема:**
- 🔵 **Синий** - `application/json`
- 🟠 **Оранжевый** - `application/xml`
- 🟢 **Зеленый** - `text/plain`

### Выделение в списке заголовков

Content-Type выделен жирным шрифтом в развернутом списке заголовков:

```
Content-Type: application/json  ← жирный шрифт
Authorization: Bearer token
Accept: */*
```

## Технические детали

### Изменения в HTML

**Было:**
```html
<div class="log-section-title">
    Исходящий запрос к Target API
</div>
<pre class="log-code json-highlight"><code>{{ .RequestBody }}</code></pre>
```

**Стало:**
```html
<div class="log-section-title">
    Исходящий запрос к Target API
    <span class="request-content-type-badge" data-headers="{{ .RequestHeaders }}"></span>
</div>
<pre class="log-code syntax-highlight" data-headers="{{ .RequestHeaders }}">
    <code>{{ .RequestBody }}</code>
</pre>
```

**Изменения:**
1. Добавлен бейдж Content-Type в заголовок секции
2. Изменен класс с `json-highlight` на `syntax-highlight`
3. Добавлен атрибут `data-headers` для доступа к заголовкам

### Логика определения типа

```javascript
// 1. Пытаемся получить Content-Type из заголовков
let contentType = '';
if (headersJson) {
    const headers = JSON.parse(headersJson);
    contentType = headers['Content-Type'] || headers['content-type'];
}

// 2. Применяем подсветку на основе типа
if (contentType.includes('json') || text.startsWith('{')) {
    // JSON подсветка
} else if (contentType.includes('xml') || text.startsWith('<?xml')) {
    // XML подсветка
} else {
    // Plain text - без подсветки
}
```

### Функция подсветки XML

```javascript
function syntaxHighlightXML(xml) {
    // Экранируем HTML
    xml = xml.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;');
    
    // Подсвечиваем элементы
    xml = xml.replace(/(&lt;\?xml[^?]*\?&gt;)/g, '<span style="color: #c678dd;">$1</span>');
    xml = xml.replace(/(&lt;\/?)([a-zA-Z0-9_:-]+)/g, '$1<span style="color: #e06c75;">$2</span>');
    xml = xml.replace(/([a-zA-Z0-9_:-]+)(=)/g, '<span style="color: #d19a66;">$1</span>$2');
    xml = xml.replace(/=(&quot;[^&]*&quot;)/g, '=<span style="color: #98c379;">$1</span>');
    
    return xml;
}
```

## Тестирование

### Тестовые сценарии

1. **JSON с Content-Type**
   - Отправить JSON с заголовком `Content-Type: application/json`
   - Проверить подсветку синтаксиса

2. **JSON без Content-Type**
   - Отправить JSON без заголовка
   - Проверить автоопределение и подсветку

3. **XML с Content-Type**
   - Отправить XML с заголовком `Content-Type: application/xml`
   - Проверить подсветку синтаксиса

4. **Plain Text**
   - Отправить текст с заголовком `Content-Type: text/plain`
   - Проверить отсутствие подсветки

5. **CSV**
   - Отправить CSV с заголовком `Content-Type: text/plain`
   - Проверить читаемое отображение

6. **Невалидный JSON**
   - Отправить невалидный JSON
   - Проверить fallback на plain text без ошибок

## Известные ограничения

1. **XML подсветка базовая**
   - Не поддерживает сложные конструкции
   - Может некорректно работать с CDATA
   - Рекомендуется для простых XML

2. **Определение типа**
   - Зависит от наличия Content-Type
   - Fallback может ошибаться для edge cases

3. **Большие файлы**
   - Подсветка может быть медленной для очень больших JSON/XML
   - Рекомендуется ограничение размера логов
