# Проекты в dmIntegroff

## Описание

Функциональность проектов позволяет группировать интеграции для лучшей организации и управления. Это особенно полезно, когда у вас много интеграций, связанных с разными системами или бизнес-процессами.

## Основные возможности

### 1. Создание проектов
- Создавайте проекты с названием и описанием
- Каждый проект отслеживает создателя
- Проекты могут содержать неограниченное количество интеграций

### 2. Управление интеграциями в проектах
- Добавляйте существующие интеграции в проекты
- Удаляйте интеграции из проектов (интеграция не удаляется, только связь)
- Создавайте новые интеграции сразу с привязкой к проекту
- Интеграция может принадлежать только одному проекту или не принадлежать никакому

### 3. Просмотр и навигация
- Список всех проектов с количеством интеграций
- Детальный просмотр проекта со всеми его интеграциями
- Быстрый переход от интеграции к проекту и обратно

## Использование

### Создание проекта

1. Перейдите в раздел "Проекты" в боковом меню
2. Нажмите "Создать проект"
3. Заполните:
- **Название** (обязательно) - например, "CRM Integration"
- **Описание** (опционально) - краткое описание проекта
4. Нажмите "Создать проект"

### Добавление интеграции в проект

**Способ 1: При создании интеграции**
1. При создании новой интеграции выберите проект из выпадающего списка
2. Интеграция автоматически будет привязана к проекту

**Способ 2: Из страницы проекта**
1. Откройте нужный проект
2. В разделе "Добавить интеграцию" выберите интеграцию из списка
3. Нажмите "Добавить"

### Удаление интеграции из проекта

1. Откройте проект
2. Найдите интеграцию в списке
3. Нажмите кнопку "" рядом с интеграцией
4. Подтвердите действие

**Важно:** Интеграция не удаляется, только убирается из проекта.

### Удаление проекта

 **Важно:** При удалении проекта автоматически удаляются все его интеграции! Это действие необратимо.

1. В списке проектов нажмите кнопку "🗑️" рядом с проектом
2. Подтвердите удаление

**Важно:** При удалении проекта все интеграции сохраняются, но становятся "без проекта".

## API Endpoints

### Проекты
- `GET /projects` - Список всех проектов
- `GET /projects/create` - Форма создания проекта
- `POST /projects` - Создание нового проекта
- `GET /projects/:id` - Просмотр проекта
- `GET /projects/:id/edit` - Форма редактирования проекта
- `POST /projects/:id/update` - Обновление проекта
- `POST /projects/:id/delete` - Удаление проекта
- `POST /projects/:id/add-integration` - Добавление интеграции в проект
- `POST /projects/:id/remove-integration/:integration_id` - Удаление интеграции из проекта

## База данных

### Таблица projects
```sql
CREATE TABLE projects (
 id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
 created_at DATETIME(3) NULL,
 updated_at DATETIME(3) NULL,
 deleted_at DATETIME(3) NULL,
 name VARCHAR(191) NOT NULL,
 description TEXT,
 created_by_id BIGINT UNSIGNED NOT NULL,
 FOREIGN KEY (created_by_id) REFERENCES users(id) ON DELETE CASCADE
);
```

### Изменения в таблице integrations
Добавлено поле `project_id`:
```sql
ALTER TABLE integrations 
ADD COLUMN project_id BIGINT UNSIGNED NULL,
ADD FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE SET NULL;
```

**Важно:** При удалении проекта `project_id` в интеграциях устанавливается в NULL (ON DELETE SET NULL).

## Миграции

Для применения изменений в базе данных выполните:

**MySQL:**
```bash
mysql -u username -p database_name < migrations/002_add_projects.sql
```

**SQLite:**
```bash
sqlite3 dmIntegroff.db < migrations/002_add_projects_sqlite.sql
```

Или просто перезапустите сервер - GORM автоматически применит миграции:
```bash
go run cmd/server/main.go
```

## Примеры использования

### Пример 1: Организация по клиентам
```
Проект: "Клиент А"
├── Интеграция: CRM → Email
├── Интеграция: CRM → SMS
└── Интеграция: Webhook → Analytics

Проект: "Клиент Б"
├── Интеграция: ERP → CRM
└── Интеграция: Payment → Accounting
```

### Пример 2: Организация по системам
```
Проект: "CRM Integrations"
├── Интеграция: Webhook → CRM
├── Интеграция: CRM → Email
└── Интеграция: CRM → Analytics

Проект: "Payment Processing"
├── Интеграция: Payment Gateway → Database
└── Интеграция: Payment → Notification
```

## Преимущества

1. **Организация** - Легко найти нужные интеграции
2. **Масштабируемость** - Управление большим количеством интеграций
3. **Командная работа** - Разные команды могут работать с разными проектами
4. **Документация** - Описание проекта помогает понять назначение интеграций
5. **Гибкость** - Интеграции могут существовать без проекта

## Ограничения

- Интеграция может принадлежать только одному проекту одновременно
- Удаление проекта автоматически удаляет все его интеграции (каскадное удаление)
- Нельзя переименовать проект через API (только через UI)
